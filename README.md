# ฅ Meow · 猫猫星绘 0.3.0

给 SillyTavern 的粉白猫猫 NovelAI 文生图扩展：独立面板、配置预设、持久图库、坏猫猫图文流程。无需构建，无需额外服务器插件。建议 SillyTavern 1.19.0+。

## 安装与更新

酒馆 → 扩展 → 安装扩展，粘贴 `https://github.com/Lumi729/meow`。已有版本点击扩展更新，完成后刷新页面。打开入口：魔法棒菜单、顶栏 ✦、右侧悬浮图片，扩展设置也有备用入口。

普通模式悬浮图片是唱片机，坏猫猫模式是「爱」。设置里可以关闭悬浮、调节 36–120px 大小、填写 HTTPS 图片链接或恢复默认位置。拖动图片移动位置；尺寸变化时会重新限制到屏幕内。

## 星绘与配置

设置页填写 NovelAI Persistent API Token 并保存。旧版本已保存的 Token、提示词和参数继续使用。

- 固定正面 + 本次描述合并为正面提示；固定负面 + 本次补充负面合并为负面提示。
- 常用参数提供独立控件：模型、尺寸、采样器、噪声计划、步数、引导、种子、Decrisper、Variety Boost、SMEA / DYN、放大。
- 已核对模型：V4.5 Full/Curated、V4 Full/Curated、Anime V3、Furry V3、Anime V2。
- 配置可以命名保存、切换、删除、导入和导出 JSON。包含绘图参数、固定提示词和高级 parameters，不包含 Token 或副 API 密钥。
- 默认节省模式限制 28 步、1MP 和不放大；关闭后可设置至 50 步、2048×2048。该限制是扩展的产品限制，不是官方完整配额。所有生成和放大都可能消耗 Anlas，不保证免费。

## 图库

生成后自动存入当前浏览器的 IndexedDB，按酒馆用户的独立标识隔离。可以筛选全部 / 当前聊天 / 坏猫猫图文。点击缩略图打开大图，点图片放大，左右滑动或上一张/下一张切换；支持下载、删除和以新种子重绘。重绘保留旧图，复用当时的参数和原文。

坏猫猫图片附有所引用原文、实际正负提示词、种子和模型。可手动插入当前来源聊天；删除图库记录不会删除已经插入聊天的副本。图库数据仅在这个浏览器里，清除网站数据会丢失，也不会自动同步到其他设备。存储失败时会提示立即下载。

## 坏猫猫：把当前故事画出来

1. 设置副 API 基础地址（例如 `https://服务商/v1`）、模型、密钥；仅支持 OpenAI 兼容 Chat Completions。
2. 导入或编辑生成 tags 的预设。支持 TXT、`system_prompt` / `prompt` / `messages` JSON，以及酒馆 `prompts` / `prompt_order`。只读取启用的文本，不执行脚本、宏、世界书或其他酒馆预设功能。
3. 在坏猫猫页设置最近 1–50 条消息、生成 1–8 张图片。
4. 按原文实际格式设置分区标记：默认 `<正文>…</正文>`、`<小剧场>…</小剧场>`、`<状态栏>…</状态栏>`。规则是字面起止字符串，不是正则。嵌套标签以外层分区为准。不匹配的内容显示“未分类原文”，默认不发送。
5. 点击捕捉，逐段勾选正文 / 小剧场 / 状态栏或未分类原文。文本框还可手动删改；最终发送预览和目标 API 明确显示。捕捉不会发请求。
6. 点击“只发送勾选内容，生成 tags”，把预设和选中原文发给副 API。返回必须包含恰好指定数量的 scenes 和有效 source_ids；格式不合格时不会自动生图，原始返回可查看。
7. 编辑返回 tags 后点击“用这些 tags 生成图片”。每张 tags 加上星绘页固定正负面，顺序生成。普通星绘的本次正面描述不会混进坏猫猫 tags。
8. 默认放入带原文的图文相册；也可选择在对应原文句子后显示插图；插图数据单独保存，不改写正文。切换聊天后需重新捕捉，防止发错原文或插错聊天。

副 API 请求上限 120 秒，NovelAI 请求上限 180 秒，无自动重试。可以停止后续任务；已经发出的请求可能仍生成并计费。失败前完成的图片会保留。

## 官网高级参数与边界

酒馆内置通道只转发有限参数；不能把未转发的参数做成假开关。因此保留稳定的酒馆通道，另提供固定目标 `https://image.novelai.net/ai/generate-image` 的官网直连（`Accept: application/json`）。直连优先复用本浏览器记住的 Token，服务器允许读取时也可使用酒馆已保存的密钥。

高级直连可填写完整 `parameters` JSON 或导入官方 generate 请求，包括 cfg_rescale、角色 v4_prompt / v4_negative_prompt、reference_* 与 director_reference_* 参数。提供一个 V4 角色提示的结构示例。主控件里的宽高、步数、引导、种子、采样器、噪声计划为准；固定正负面始终合并到 base_caption；每次一张。直连请关闭酒馆放大与 Variety Boost，使用官网对应参数。

**尚未做到官网全部交互界面。** Vibe / Precise Reference 的编码和上传编辑器、官网画布、局部重绘、Director Tools 暂未实现；不能将这里称为完整官网克隆。官方文档现在列有 V5，但机器 schema 不枚举模型标识，已核对的酒馆源码尚未提供 V5 标识，因此不猜测预填。支持手动填写从官方请求确认的模型 API 标识。

官网直连可能受浏览器 CORS 或网络策略限制，未进行真实 Token 调用；遇到跨域问题可切回酒馆通道。不会绕过浏览器保护或启用公共代理。

## 密钥与隐私

NovelAI Token 存到当前酒馆服务器的原生密钥管理。副 API 使用酒馆 Custom 密钥管理并绑定具体 ID；保存时也会更新酒馆 Custom 当前密钥，已有密钥保留在密钥管理中可切换。地址、模型、预设、密钥 ID 可以在设置中保存，密钥值不进扩展设置、导出、图库或仓库。官网直连额外在当前页面闭包中保留用户刚输入的 Token，刷新后释放。

坏猫猫只发送勾选文本与 tags 预设，不自动发送角色卡、世界书、未选状态栏或系统消息。图片数据和原文只保存在用户端 / 用户酒馆中，不上传 GitHub。自定义悬浮图片链接会访问对应地址，默认素材随仓库附带。图库包含原文，请按聊天隐私对待。

### 0.4.0 正文插图
绘图参数移动到「猫猫，开始画画」下方的折叠区。每条聊天正文下新增「给这段正文生成图片」，点击进入坏猫猫选择原文、生成 tags，再生成图片；默认输出到相册并插入原消息中，不新增聊天消息。若在原文选择框中保留唯一的一小段原文，则插在这小段后；无法唯一匹配的改写内容仍绑定最初捕捉的整段。跨消息引用会在各自来源段后插入同一图片。
正文图片支持点开放大、重绘、左右滑动或箭头切换版本；大图中可删除正文版本，图库原图保留。相同原文的新图组成版本组，正文只显示当前版本。图片先上传到本地酒馆图片目录，正文及当前回复 swipe 保存图片链接；版本和实际请求保存在消息 extra。切换聊天、编辑原文或删除定位标记后会阻止旧图写入，图片留在图库。
插图会把 Markdown 图片标记写入原 mes 文本，因此后续酒馆上下文可包含该图片链接。本扩展重新捕捉时会去掉自己的图片标记。用户自定义正则、iframe 美化可能影响原文内图片显示；没有对用户手机的自定义美化做真实验证。已有“新消息”图不会自动搬回原文。
速度截图显示请求及下载 124.2 秒，解码和保存各 0.1 秒；无法仅凭此区分官方排队/生成和网络耗时，本版没有宣称缩短上游时间。

### 0.5.0 正文保护、人物资料和预览修复
新版插图保存在 message.extra.meow_inline，不再向 message.mes 写 Markdown，不调用整条消息重渲染接口。每个场景只插一次，按副 API 返回的逐字原文句子定位；多段资料可共同描述一张图。重绘显示进度，完成只更新图片；每张插图均可独立删除，左右换版本。普通正文及可访问的 iframe 支持句后定位；封闭 iframe 或美化隐藏/改写了句子时，保留原有页面，在楼层下显示带原文的插图卡，不修改美化代码。旧 0.4.x 已写入的标记需在设置点一次「修复旧版正文插图并刷新」，保留图片并清理原文及 swipes 的旧标记。

坏猫猫首次生成 tags 前扫描当前角色卡、群聊成员卡、用户人设、角色内置及关联世界书、聊天/人设/全局绑定世界书；不扫描未关联的其他角色书。未触发但启用的外貌设定也可提取。资料框可核对编辑、重新扫描或关闭发送；监控视角共用资料。提取采用外貌关键词与相邻行，可能遗漏特殊格式，不能保证每个模型绝对保持外貌。关闭的世界书条目不自动使用。

直连 Token 可保存在当前浏览器独立 IndexedDB，与绘图配置导出分离，刷新复用；设置可关闭记忆或清除。旧用户如酒馆禁止读取服务器凭证，需在本版本保存一次，此后不必每次填写；更换浏览器或清除网站数据后需要重新配置。

星绘和坏猫猫各有独立图片预览框，可左右翻页；放大预览切图后关闭，会保持所选图片。正文 content 标签的内部不完整 HTML 不再拆散外层正文。测试覆盖原文与代码块完整性、多来源单次插图、删除/重绘反馈、句子定位、角色书扫描、本地凭证和双预览同步。未使用用户真实密钥进行付费生图，用户自定义 iframe 仍需实机验证。

### 0.5.4 监控画面管理、手写预览与自动保存

- 点监控屏上的画面会直接打开猫猫大图窗口（自带重绘和删除，左右翻只翻这块监控屏的画面），监控屏平时不加按钮；监控屏也可以用消息请求打开、重绘或删除自己的画面（消息 meow-camera-view / meow-camera-redraw / meow-camera-delete，带图片 id 与当前 records）；在图库大图里重绘或删除监控画面，也会同步刷新已打开的监控屏。
- 人物外貌扫描只收人物：需要至少两类外貌描写（发、眼、身材、脸、服装），标题像世界观、规则、副本、待整理等条目直接跳过；「陈野衣柜」这类带人物名的附属条目保留。用户人设即使不在世界书里也会出现，没写描述时建空白档案。重新扫描会移除旧版扫进来且没改过的非人物条目。
- 「将发送的原文预览」可以直接改写或手写，不捕捉也能发给副 API 生成 tags；这类图放进图文相册，不插入正文。
- 捕捉的原文、预览框内容、返回的 tags（包括监控镜头 tags）按聊天自动保存在本浏览器，关掉面板、切出去或刷新后回来都还在。
- 大图下方「这张图来自这句原文」只显示插图对应的那一句，完整原文折叠在「查看完整原文」里。
- 绘图配置下拉框记住上次选的配置。

### 0.5.3 副 API 密钥不再顶掉酒馆主密钥

- 保存副 API 密钥后，自动把酒馆 Custom 当前密钥切回原来那把；Meow 继续按自己的密钥 ID 调用副 API，主聊天不受影响。

### 0.5.2 监控原文背景与 JSON 输出协议
监控 tag 请求现在包括所选镜头、本条完整消息原文（original_context，界面只读预览）、人物档案及用户保存的坏猫猫 tag 预设，再附加监控视角要求。原文用于理解时间、地点和关系，所选住宅记录决定实际镜头；不读取其他聊天消息。因为用户选择完整本条原文，原文中其他状态栏内容也会作为背景发送给已配置的副 API。旧版“只发送住宅记录”说明只适用于 0.5.1 及之前。

普通坏猫猫与监控请求共用更明确的 JSON 输出协议，要求一个对象、准确 scenes 数量、英文双引号、正确类型、有效原文 id 与逐字引用，禁止 Markdown、注释和尾随逗号。坏猫猫界面提供可对照的普通模式完整示例。上游 finish_reason 为 length 时提示输出截断；没有自动重试或自动付费生图。格式提示无法保证每个模型必然遵守，返回仍会先做解析和字段校验。33 项测试及界面模拟通过，未调用用户真实付费 API。
